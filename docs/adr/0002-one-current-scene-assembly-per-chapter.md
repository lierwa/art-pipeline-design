# One current scene assembly per chapter

A Scene Category is a planning container for multiple chapters; UI and code should stop naming this layer as a bare Scene because a Chapter owns the Chapter Scene Package for one playable scene. Existing `ScenePack` code concepts should migrate toward `SceneCategory`, while persisted legacy paths and payloads can remain compatible during the transition. Earlier Prompt Version and Image Attempt workflows existed to iterate on the hope that one prompt could produce a complete Image2 scene, but the new workflow separates the Chapter Scene Prompt, base-scene selection, complete-scene images, pipeline-produced assets, and final assembly; the old Prompt Version and Image Attempt workflow should be removed instead of kept as a parallel chapter scene source. Chapter production progress is derived from the Chapter Scene Package contents instead of persisted as a second status source. Future upgrades to the same chapter scene can be modeled later when that need appears.
